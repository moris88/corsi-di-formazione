# Vocabolario dei termini di GitHub

Glossario alfabetico dei termini del programma d'esame. Tra parentesi il dominio in cui compare.

## A

**Action** — blocco riutilizzabile di un workflow di GitHub Actions (D4).
**Admin** — ruolo con accesso completo a un repository (D6).
**Assegnatario** — persona responsabile di un'issue o di una pull request (D3, D5).

## B

**Branch (ramo)** — linea di sviluppo indipendente (D1).
**Branch protection** — regole che proteggono un ramo, come richiedere revisioni (D6).

## C

**Clone** — copia locale di un repository remoto (D1).
**CODEOWNERS** — file che indica i responsabili di certi percorsi (D2).
**Codespaces** — ambiente di sviluppo nel cloud basato su dev container (D4).
**Commit** — istantanea registrata delle modifiche (D1).
**Copilot** — assistente di programmazione basato su IA (D4).

## D

**Dependabot** — strumento per avvisi e aggiornamenti delle dipendenze (D6).
**Dev container** — contenitore configurato come ambiente di sviluppo (D4).
**Discussions** — spazio per conversazioni aperte in un repository (D3).

## E

**EMU (Enterprise Managed Users)** — account gestiti dall'azienda tramite il suo provider di identità (D6).

## F

**Fork** — copia personale di un repository di un altro utente da cui proporre modifiche (D7).

## G

**Gist** — frammento di codice o appunto condiviso, con cronologia Git (D3).
**GitHub Flow** — flusso di lavoro basato su rami brevi e pull request (D1).
**GitHub Pages** — hosting di siti statici da un repository (D3).

## I

**InnerSource** — pratiche open source applicate dentro un'azienda (D7).
**Issue** — attività, bug o richiesta da tracciare (D3).

## L

**Label (etichetta)** — categoria applicata a issue e pull request (D5).

## M

**Markdown** — linguaggio di formattazione del testo (D1).
**Marketplace** — catalogo di app e Actions (D7).
**Merge** — unione di un ramo in un altro (D1).
**Milestone (attività cardine)** — obiettivo con data a cui si associano issue (D5).

## P

**Passkey** — credenziale senza password resistente al phishing (D6).
**Project** — strumento di pianificazione con tabella, bacheca e roadmap (D5).
**Pull request** — proposta di modifica da rivedere prima del merge (D3).

## R

**README** — file di presentazione di un repository (D2).
**Repository** — progetto con la sua cronologia (D1).
**Runner** — server che esegue i job di Actions (D4).

## S

**Saved reply** — risposta riutilizzabile per i commenti (D5).
**Sponsors** — sostegno economico a chi sviluppa open source (D7).

## T

**Template** — repository usato come modello per crearne di nuovi (D2).
**Triage** — ruolo che gestisce issue e pull request senza scrivere codice (D6).

## W

**Wiki** — documentazione multipagina di un repository (D3).
**Workflow** — processo automatico di GitHub Actions in un file YAML (D4).
